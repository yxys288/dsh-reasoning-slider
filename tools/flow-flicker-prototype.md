# 流动粒子的逐粒子闪烁：候选对比与选型

> 任务：档位条「已填充」段上的流动微粒，从"整层一致"改成**一颗颗粒子各自明灭（相位错开）**，
> 审美保持克制（白点落在蓝色填充上，不闪成霓虹灯）。
>
> 结论：**选 P2「反相梳对」**。每层配一条半周期错位、周期翻倍的副梳（伪元素），
> 与主梳等速漂移、反相明灭——净点距、行进线速度、峰值亮度全部与现网一致，
> 只多出逐粒子相位差。已落到 `lib/client.js`，并由 `tests/flow-flicker.test.mjs` 钉住。

## 1. 四个实现（含一个对照）

| | 做法 | 原理 | 新增 DOM | 合成器友好度 | 与 mask / 不压白钮冲突 | 实测（light，tracked 口径） |
|---|---|---|---|---|---|---|
| **P0 对照** | 出货现状：两层点阵纯平移 | 只有平移，没有明灭 | 无 | 纯 transform ✓ | 无 | 幅度 1.07（=地板）、反相对 0/3、判读 **no-measurable-twinkle** |
| **P1 整层相位呼吸** | 两层各挂一条 `opacity` keyframe，时长/相位不同 | 整层透明度呼吸 | 无 | transform+opacity ✓ | 无 | 幅度 8.60（8.0× 地板）但**同相度 0.921、反相对 0/7** → **lockstep-pulse**（正是用户否掉的"整层脉冲"） |
| **P2 反相梳对（选定）** | 每层配一条副梳：`left` = 半个载波周期、载波周期翻倍，两梳共用同一 drift keyframes、twinkle 用互为镜像的 keyframes | 相邻粒子恒处于周期两端 → 逐粒子反相 | 无（伪元素） | transform+opacity ✓ | 无（副梳是 `.drs-flow` 的伪元素，被 overflow/mask 裁切，不进入圆钮区域） | 幅度 **12.49（11.6× 地板）**、同相度 **0.165**、空间极差 **1.954**、**反相对 3/7** → **staggered-antiphase** |
| **P3 步进超胞** | 4 格超胞（每格 alpha 不同）+ `steps(4)` 位移 | 每跳一格，粒子继承下一格 alpha → 相位天然错开 | 无 | 纯 transform ✓（但位移是跳格） | 无 | 幅度 14.44（13.5× 地板）、反相对 6/10 → staggered-antiphase；**但流动变成每 800ms 跳 16px**，且明灭幅度约为 P2 的 1.2 倍，不够克制 |

三者的共同点（也是硬约束）：都不写 rAF/定时器/canvas，动画只碰 `transform` 与 `opacity`；
覆盖层保持 `pointer-events:none`；宽度公式不变，因此粒子永远停在白色圆钮左缘。

## 2. 为什么选 P2

1. **逐粒子相位是真的**：相邻粒子恒反相（同一个 `animation-duration` + 镜像 keyframes ⇒ 精确反相，
   不会随时间漂移），两条车道又用不同节拍（2.15s / 3.45s），整个场不会退化成"一起呼吸"。
2. **形制零改动**：载波周期翻倍 + 副梳偏移半周期 ⇒ 合成净点距与现网**逐点相同**
   （A 层 4+32k 与 20+32k ⇒ 4+16k；B 层 13+54k 与 40+54k ⇒ 13+27k），
   漂移时长同比放大（3.2s/32px、5.8s/54px）⇒ 线速度仍是 10.0 / 9.31 px/s。
3. **只变暗、不变亮**：主梳 alpha 仍是 `.55`，副梳 `.42`/`.24`，twinkle 上限 `opacity:1`、暗相 `.5`
   ⇒ 任何时刻没有任何白点比现网更亮（合成峰值 = 现网峰值），符合"克制"。
4. **两条逃生口都覆盖**：reduced-motion 与锁定的 seat 把副梳动画一并关掉/暂停。

## 4. 证据抓到一个真 bug（值得记下来）

第一版 P2 把副梳写成**被动画那一层的** `::before`（`.drs-flow-a::before`）。
CSS 上一切正常——`getComputedStyle(::before).opacity` 确实在 1.0↔0.5 之间摆——
但**像素上副梳的亮度恒定不变**：成对帧里只有主梳站点变亮，副梳站点一个都没变。

原因：`opacity` 会以"组透明度"乘到子树，副梳是那一层的子元素，于是
观测亮度 = 副梳 opacity × 父层 opacity = `0.5×1` == `1.0×0.5` —— **反相被精确抵消**。
证据就是"同位置成对帧"这个口径：它把几何、mask、位移全部消掉，只剩下动画值这一个变量，
所以一个"看起来对"的 CSS 才会暴露成"像素上什么都不动"。
修法：副梳挂到容器 `.drs-flow` 上（`::before`/`::after`），自己带一份与所在车道同参数的 drift，
反相因此成立。`tests/flow-flicker.test.mjs` 里专门留了一条断言禁止再把它嵌回动画层里。

## 5. 读法上的诚实说明

* `Δt=800ms` 那一行对 P0/P1/P2 而言是**半个点距的位移**，不是几何重合（位移 8px = 16px 点距的一半），
  所以它们的"100% 反相"是**运动伪影**，不能当作明灭证据；只有 P3 在 800ms 处几何真正重合（整格 16px）。
  判定用的行是 `a @3200` 与 `b @5800`。
* P1 在 `a @3200` 出现"无变化"是**相位巧合**（2.4s 周期 + 0.7s 负延迟，两个采样点都落在 ≈0.82 的同一相位上），
  所以 P1 的反相/同相结论以 lane B 的 `b @5800`（0/4 全变暗）与 tracked 口径（同相度 0.92、反相对 0/7）为准。
* 追踪口径的"粒子数"在个别宽度上会退化成 1（粒子漂出采样带被整条丢弃，宁缺毋滥），
  那些宽度被标成 `insufficient-particles`，不参与判读。
* 无头 Chrome 的虚拟时间**不**驱动动画时钟，所以时序帧一律靠显式 `seek`；"在跑"由真实时钟探针单独证。
* 证据里 `flow-flicker.profiles.json` 是**原始**逐列亮度矩阵（未做任何修正），
  mask 增益修正发生在分析阶段（`.drs-flow` 的左淡右亮渐变会随粒子左移产生单调下降，
  不做修正会伪造出"整层同相"的信号）。
